# W10a: firmware encoding and complete validation replay
Selection rule fixed before W10a outcomes (2026-11-06): on the first 150 official trainval TRAIN scenes in name order, choose the encoding with the largest T system ACCEPT count, subject to registered-oracle FA(T) and FA(H) rates each no higher than E0 on that training sample. Compare exact fractions; undefined FA makes a candidate ineligible. E0 is the baseline fallback. Break ties by E0, E1, E2 order. Validation outcomes cannot change this choice.
Training uses available saved train_pred_hw_new.npy tokens in these scenes (stride-12 training extraction), restricted by the unchanged W7 eligibility/ODD filter; no training prediction is substituted. Continuous service spans the scene, with packets only at available eligible tokens. Report token coverage explicitly.
E0: original origin/0.5/1.0 s interpolating quadratic. E1: degree-2 least squares, hard q(0)=0, equal unit residual weights at 0.5/1/1.5/2 s (origin has zero residual). E2: propagate measured snapshot x/v with measured acceleration for 0.1 s (stop-clipped golden advance); command acceleration is clipped E1 q-double-prime in [-8,2].
TSM certifies the bridge and selected stopping tail from the encoded apply state in the supplied scalar world, conditional on existing timing/state assumptions; it does not certify tracking the four planner waypoints. E2 conveys acceleration intent only.
A planner transaction owns seq, generated epoch, snapshot and apply epoch. Firmware may encode a newly completed transaction once, and must preserve that packet on retry: it must not refresh timestamps, sequence, measured anchor or CRC when a planner freezes. Stale snapshot -> freshness; identical packet -> sequence; absent new samples -> freeze_no_sample; identical encoded state with fresh metadata and ego displacement -> freeze. Unchanged waypoints repackaged with new measured anchors are NOT detectable as frozen by this ABI; host must enforce transaction ownership.
