# R1 decisions ??? TSM-X, TSMX project, version 0.1

The designer delegates all design and verification decisions in the R1 request.
Every decision below is a supervisor ASSUMPTION under that delegation. Only B7,
B8, B10 and their listed common contracts are implemented. No source under
golden/, spec/, vectors/ or verify/ is edited by this work.

| ID | ASSUMPTION / decision and source |
|---|---|
| DEV-001 / ASSUMPTION | The user's delegation supersedes skill R-005/R-006, the port-list confirmation gate, and any R-026 wait. New files implement the requested three modules; no existing RTL baseline was present. |
| DEV-002 / ASSUMPTION | Scan only `R1_SPEC_EXTRACT.md`, a snapshot of permitted clauses, to honor the read restriction and avoid concurrent codec work. R-004 scanner's G-001..G-014 missing-template BLOCK findings are not behavioral gaps: common ports, clock/reset, data format, functions and error paths are in the supplied block clauses. Mark all 14 not applicable to this scoped excerpt. `R1_gap_scan.log` preserves them. |
| DEV-003 / ASSUMPTION | Interfaces are exactly spec 5.3/5.5.7/8/10: clock/reset and request/response valid-ready; B7 16/16 bits, B8 44/8, B10 1056/32, plus B10 10-bit indexed read with independent valid-ready response. No state injection ports. |
| DEV-004 / ASSUMPTION | Each acceptance registers its response at the sampling edge (one cycle latency). BOOT inhibits ready during reset; first released edge enters IDLE. RESP holds until consumed, then returns to IDLE. No same-edge replacement: maximum steady rate one acceptance every two clocks with ready consumers. Bounds are B7 <=64, B8 <=32, B10 <=2. Consumer stalls extend holding time, not computation latency. |
| DEV-005 / ASSUMPTION | Leaf reset input is already synchronized on release by the system wrapper (spec 7); do not duplicate a reset synchronizer or add DFT/test controls in these leaves. Asynchronous assertion clears control and payload, even during a stalled response. No clock gating or CDC in these blocks. |
| DEV-006 / ASSUMPTION | B7 uses fixed `PARA_PROFILES=16`, mask 0x7777, increasing eligible numeric ID, candidate15/label2 for the empty pool, otherwise label1 (5.5.7/9.2). Overrides of the locked parameter are outside the contract. No persistence or memoization. |
| DEV-007 / ASSUMPTION | B8 is a stateless proposal, including clear flags; top owns good/mode/fault and the actual records. Invalid mode6/7 is treated as health=false, including when accept is true, as required by 5.5.8/9.2. Physical reset yields invalid zero response; a reset request yields HOLD/L3, good0/fault1/clear-both. Incoming fault does not change the stated precedence. |
| DEV-008 / ASSUMPTION | B10 depth is an elaboration parameter 1..1024 (default64); golden fixtures run with depth4. An 11-bit count represents 1024; 10-bit head/index represent 0..1023. Address sums use 11 bits with explicit modulo correction, supporting non-power-of-two depths. No pop on read. |
| DEV-009 / ASSUMPTION | B10 validates the Event ABI: schema flag, count<=4, integer length0, integer upper192 bits0, string length<=32 bytes, unused bytes and slots0. The typed frontend supplies actual UTF-8; reachable strings are ASCII enums per 5.5.10. `valid_schema=0` preserves invalid original types/overlong strings before packing. Canonical malformed packed records are rejected as well. |
| DEV-010 / ASSUMPTION | Preserve golden b10_rec's strict integer lower bound: -2^63 is invalid, -(2^63)+1 and (2^63)-1 are valid. The apparent s64 range description does not override the explicit golden predicate. Invalid events increment saturated lost without changing any ring entry or pointer. |
| DEV-011 / ASSUMPTION | Out-of-range indexed reads are unspecified: complete with valid=1/data=0 in one cycle. Such a read never changes count/head/lost. A read accepted with a write observes the old indexed snapshot, not forwarded write data (5.5.10). Stalled snapshots stay immutable across later overwrites. |
| DEV-012 / ASSUMPTION | The independent log response slot never gates write acceptance. Writes may wait only for their own outstanding response, consistent with the one-outstanding common contract. Reading invalid RAM is prevented by count; reset need not clear payload RAM. RAM inference/technology mapping awaits synthesis. |
| DEV-013 / ASSUMPTION | Pack ports.jsonl by semantic names, then compare the entire physical response vector; B10 additionally compares every bit of each retained Event through indexed reads. Validate original fixture hex SHA256 and applicable semantic fields/digests. Fixture-only CRC/digest/state fields are not invented as RTL ports. B8's nonphysical retained fields are checked as unchanged in conversion. |
| DEV-014 / ASSUMPTION | Directed B7 expectations independently enumerate eligible IDs for all65536 masks. B8 expectations enumerate 8192 combinations of mode/good/fault/accept/speed/reuse/fallback/cap/reset/health. B10 expectations track a separate bounded Python list, malformed events, simultaneous reads/writes, chronological snapshots and lost saturation. No expected result is extracted from RTL. |
| DEV-015 / ASSUMPTION | Icarus-compatible clocked immediate assertions replace unsupported concurrent/named assertion syntax. Each assertion has a spec clause, hit count and nonzero-exit failure; baseline runs fail on any zero-hit assertion. The supplementary depth runs exercise a declared subset; the full assertion activity obligation is checked at fixture depth4. No standard APB/AXI protocol exists on these project leaf ports. |
| DEV-016 / ASSUMPTION | Demonstrate every assertion with its own actual DUT-output stuck-X force injection, enabled by +MUTANT=id in verification only. These are output fault mutants, not changes to an assertion expression. Also run four functional RTL source mutants per block on separate copies. Keep commands, exit codes, targeted assertion failures and exact source replacements under each TB directory. No mutation affects delivered design RTL. |
| DEV-017 / ASSUMPTION | Saturation setup deposits 0xfffffffe into recorder lost state in the TB, avoiding 2^32 writes; subsequent increments/saturation and reset use real handshakes. Additional depths1/3/64/1024 use real append/overwrite/read operations, no internal ring-state peeking. |
| DEV-018 / ASSUMPTION | The first supplementary depth1024 run revealed that the test's index1023-invalid assertion was overbroad. Spec allows all1024 entries. Limit that assertion to depth<1024; no RTL behavior changed to fit the test. Icarus assertion labels were changed to named surrounding blocks for compiler compatibility. |
| DEV-019 / ASSUMPTION | Use the Moore example's enum state / next-state / state-only output split for all common handshakes; B8's transform and B7's reduction are pure combinational payload computations. Recorder adds an independent registered snapshot channel. Header/skeleton follow the requested VLSIT rule file v2. |
| DEV-020 / ASSUMPTION | R-017 utility requires a unique top and omits unreachable leaf tops. Generate a filelist per block with the utility, then mechanically aggregate those lists into filelist_R1.f. Lint each of the three tops against the aggregate. No artificial design wrapper is added. |
| DEV-021 / ASSUMPTION | No supported lint tool found: preserve all R-015 logs and report lint not run. Icarus elaboration is not lint. No installation is attempted; supervisor's later Verilator run is outside this execution. |
| DEV-022 / ASSUMPTION | No claim of synthesis, RAM inference, timing, CDC/RDC signoff, scan insertion, or formal proof is made. Source-level inspection and simulation cover this RTL wave only. No design behavior depends on SYNTHESIS or any other conditional build macro. |

Reproduction: run `python tsmx_hw/tb/unit/check_R1.py` and

the source generation recipe; it is not needed to rerun verification.
