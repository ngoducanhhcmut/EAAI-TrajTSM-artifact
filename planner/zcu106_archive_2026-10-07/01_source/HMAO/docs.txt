1. ĐỊNH NGHĨA & MỤC TIÊU THIẾT KẾ

1.1 Tên & Nhiệm Vụ
Tên đầy đủ: HMAO Engine = Hardware-Managed Assurance Offload Safety Verification Engine
Với mỗi quỹ đạo (trajectory) đề xuất từ Planning Accelerator, HMAO Engine thực hiện hai bước:

• Tính toán tập hợp trạng thái xe có thể đạt được trong 5 giây tới (Reachable Set) sử dụng lý thuyết Zonotope Reachability Analysis.
• Kiểm tra xem tập hợp đó có giao nhau với bất kỳ chướng ngại vật nào trong World Model không.
• Nếu có giao nhau → OUTPUT VETO (từ chối quỹ đạo, kích hoạt MRM).
• Nếu không giao nhau → OUTPUT GRANT (chấp thuận thực thi quỹ đạo).

• Disable AI Accelerators
• HMAO VẪN RUNNING (cho post-mortem analysis)

7.2 Sub-Module 2: Zonotope Reachability Unit
7.2.1 Lý Thuyết Zonotope
Zonotope: Z = { c + Σi αi×gi | αi ∈ [-1, 1], i = 1..n }

Trong đó: c = center vector (tâm), gi = generator vectors, αi = hệ số scaling.

<table> Tính Chất Ý Nghĩa Thiết Kế Zonotope là convex set → Collision check hiệu quả bằng SAT Luôn over-approximate reachable set → Đảm bảo ZERO FALSE NEGATIVES (ASIL-D) Minkowski sum của 2 zonotope = zonotope → Đóng dưới phép tổng Minkowski (giữ nguyên cấu trúc) Linear transformation của zonotope = zonotope → Dễ dàng áp dụng ma trận động học A, B </table>
7.2.2 Vehicle Dynamics Model – Ma Trận A và B (Giải pháp Gap #16, #17)
State vector: x = [px, py, v, θ]^T. Control input: u = [a, δ]^T (gia tốc và góc lái). Phương trình: x(t+1) = A×x(t) + B×u(t) + w(t)

<table> 1 0 Δt·cos(θ_k) -v_k·Δt·sin(θ_k) 0 1 Δt·sin(θ_k) v_k·Δt·cos(θ_k) 0 0 1 0 0 0 Δt·tan(δ_k)/L 1 </table>

7.3 Sub-Module 3: ADMM Solver
7.3.1 Vai Trò & Cách Hoạt Động
ADMM Solver chạy SONG SONG với Zonotope Unit (tiết kiệm 2-3ms so với tuần tự). Kết quả ADMM dùng để confirm/refine collision check từ kết quả hình học Zonotope.

7.3.2 Thiết Lập Bài Toán ADMM (Giải pháp Gap #19)
Bài toán tránh va chạm được chuyển hóa thành Convex Programming: min f(x) + g(z) s.t. Ax + Bz = c

<table> Thành Phần Định Nghĩa Biến x Quỹ đạo động học của xe tự hành Biến z (slack) Khoảng cách tối thiểu từ điểm kiểm tra của xe đến bề mặt vật cản Hàm f(x) f(x) = 0 (HMAO chỉ kiểm chứng, không tạo quỹ đạo mới) Hàm g(z) - barrier g(z) = +∞ nếu z < d_safe (vi phạm) | g(z) = 0 nếu z ≥ d_safe (an toàn) Ma trận ràng buộc A = I, B = -I, c = 0 → z phải phản ánh chính xác vị trí x chiếu trên không gian an toàn </table>
7.3.3 Gỡ Cuộn Vòng Lặp (Giải pháp Gap #6, #9)
Để đảm bảo ASIL-D (latency tĩnh), ADMM được unroll thành static pipeline chính xác 15 tầng. KHÔNG có feedback loop - dữ liệu chỉ chảy một chiều qua 15 stages.

10.2 Quản Lý Vật Cản Đáng Ngờ & Priority Sorting (Giải pháp Gap #20)

TTC = Δx / v_rel (xấp xỉ bằng phép dịch bit trên phần cứng)

• Vật cản có TTC nhỏ nhất (nguy cơ sớm nhất) → đẩy lên đỉnh hàng đợi
• Vật cản có TTC lớn (xa, nguy cơ thấp) → loại bỏ khỏi danh sách kiểm tra
• Đảm bảo HMAO không bỏ sót rủi ro chí mạng ngay cả khi bị quá tải bộ nhớ

17. RTL CODING RULES (ASIL-D COMPLIANCE)

17.1 Determinism Rules
• REQUIRED: Blocking assignments trong combinational logic
• REQUIRED: Non-blocking assignments trong sequential logic
• REQUIRED: Tất cả signals phải có giá trị default (không uninitialized)
• REQUIRED: Tất cả case statements phải có default branch
• ILLEGAL: Gated clocks (clock gating bị cấm trong ASIL-D)
• ILLEGAL: Combinational feedback loops
• PROHIBITED: Latches (phải là FF-based)

17.2 Latency Predictability Rules
• REQUIRED: Tất cả paths fully pipelined – không có variable-depth loops
• REQUIRED: Không có conditional logic trên critical timing path
• REQUIRED: Registered outputs tại mỗi pipeline stage
• REQUIRED: Document latency/cycle count cho mỗi block (comment trong RTL)
• REQUIRED: Fixed pipeline depth – ADMM MUST be unrolled (15 stages)

17.3 Resource Bounds & Error Detection
• REQUIRED: Không có unbounded counters (max width phải defined)
• REQUIRED: Tất cả arrays fixed-size tại elaboration
• REQUIRED: Bounded FIFO depths (power-of-2)
• REQUIRED: Parity bits trên critical data buses
• REQUIRED: CRC trên transmitted/received packets
• REQUIRED: Watchdog timers trên tất cả state machines
• REQUIRED: Duplicate comparison logic cho critical outputs
• REQUIRED: Formal assertions tại key decision points
• REQUIRED: Traceability to requirements (RTL2Req)
